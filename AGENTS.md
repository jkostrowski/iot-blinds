# Repository Guidelines

## Project Structure & Module Organization
- `src/main.cpp` holds the firmware entry point and core logic for the blinds controller.
- `lib/` contains project-specific libraries (`AH_EasyDriver`, `SimpleTimer`).
- `include/` is available for shared headers (currently minimal).
- `lib-old/` keeps legacy library versions (do not modify unless intentionally reviving).
- `.pio/` is generated by PlatformIO (build artifacts, local libs).
- `.github/workflows/build.yml` defines CI compile checks.
- `Schematic.jpg` documents the hardware wiring reference.

## Build, Test, and Development Commands
- `pio run -e OTA4` builds the firmware for the `OTA4` environment.
- `pio run -e OTA4 -t upload` uploads via OTA to the configured device.
- `pio run -e COM -t upload` uploads over serial (see `platformio.ini` for port).
- `pio run -e OTA3 -t upload` uses the reversed-direction environment.
- `arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 ./src` mirrors CI compile.

## Coding Style & Naming Conventions
- Language: Arduino C++ for ESP8266 (`nodemcuv2`).
- Indentation: 2 spaces; braces on the same line as control statements.
- Constants and pins use `ALL_CAPS`/`STEPPER_*` style macros.
- Function names are short and descriptive; follow existing mix of `lower_snake` and `lowerCamel` near the edited code.
- Keep MQTT topics in the existing `MQTT_CLIENT"/cmd"` pattern to avoid breaking clients.

## Testing Guidelines
- No unit test framework is present. Validation is build + device integration.
- At minimum, run a local build (`pio run -e <env>`) before PRs.
- When changing behavior, include a brief manual test note (e.g., “OPEN/CLOSE on OTA2 verified”).

## Commit & Pull Request Guidelines
- Commit history favors short, present-tense messages (e.g., “cleanup”, “working”, “position on boot”).
- Keep subjects under ~50 characters; avoid heavy formatting.
- PRs should include the target environment (`COM`, `OTA1`–`OTA4`), steps tested, and any hardware or wiring assumptions.

## Security & Configuration Tips
- WiFi/MQTT credentials are currently defined in `platformio.secret.ini`
- Prefer local overrides in `platformio.secret.ini` to avoid committing real secrets.
- If you add new config flags, document them in `platformio.ini` and reference them in the PR description.
